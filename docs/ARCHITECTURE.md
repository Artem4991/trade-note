# Архитектура Trade Note

## Принципы

- Offline-first: первая версия полностью работает в браузере без сервера.
- Минимум зависимостей: платформенные API и небольшие локальные модули предпочтительнее скрытых абстракций.
- Архитектурная граница появляется только вместе с конкретной ответственностью.
- Persisted-данные и финансовые вычисления имеют явные форматы и покрываются тестами.

## Технологии

- Vue 3 с Composition API и `<script setup lang="ts">`.
- TypeScript в строгом режиме.
- Vite для разработки и сборки.
- Naive UI как компонентная библиотека.
- pnpm workspaces для монорепозитория.
- ESLint, Prettier и Vitest для контроля качества.

Vue Router, Pinia, TanStack Query и Turborepo не подключаются до появления конкретной потребности.

## Frontend и FSD

- Используется pages-first подход: однократно используемые UI, модель, состояние и действия остаются внутри `pages/portfolio`.
- `features` и `entities` выделяются только при текущем повторном использовании, независимой причине изменения и сфокусированной ответственности.
- `widgets` не создаются без доказанной необходимости в переиспользуемой композиции.
- Направление зависимостей: `app -> pages -> widgets -> features -> entities -> shared`.
- Слайсы одного слоя не импортируют друг друга напрямую и предоставляют публичный API через `index.ts`.
- Повторяемые прикладные обёртки над Naive UI помещаются в `shared/ui`.

## Хранение данных

- IndexedDB скрыта за собственной Promise-based библиотекой и репозиториями.
- `packages/indexed-db` не зависит от Vue и бизнес-моделей портфеля.
- Vue-компоненты не обращаются к IndexedDB напрямую.
- Транзакция считается успешной только после события её завершения; ошибки явно передаются вызывающему коду.
- Реактивное обновление выполняется явным событием после успешной транзакции.
- Межвкладочная синхронизация через `BroadcastChannel` добавляется только при необходимости.
- Для каждого изменения схемы заранее определяются версия, миграция и поведение существующих данных.

## Финансовые значения

- Деньги, количество и курсы сохраняются как канонические десятичные строки.
- Вычисления выполняются локальными функциями на основе `bigint` с явным масштабом и округлением.
- `number` не используется для сохраняемых финансовых значений.
- Парсинг, масштабирование, умножение, конвертация и округление покрываются unit-тестами до использования в расчётах портфеля.

## Адаптивность и PWA

- Поддерживаются два режима интерфейса: mobile/tablet и desktop.
- PWA подключается после появления рабочего портфеля отдельным этапом.

## Quality gates

- Prettier отвечает за форматирование: обязательные точки с запятой, одинарные кавычки, trailing commas, LF и `printWidth: 140`.
- ESLint работает без допустимых warnings, проверяет строки длиннее 140 символов, type-aware TypeScript-правила, Vue SFC и направление FSD-импортов.
- TypeScript и `vue-tsc` проверяют код в строгом режиме без генерации JavaScript.
- Vitest отвечает за поведение; временно разрешено отсутствие тестов до появления первого тестового файла.
- Vite выполняет production-сборку как отдельный обязательный барьер.
- `pnpm check` запускает быстрые проверки форматирования, ESLint и типов.
- `pnpm verify` выполняет все quality gates и `git diff --check`, не останавливаясь на первой ошибке, и печатает итоговую сводку.
- Будущий CI должен устанавливать зависимости через `pnpm install --frozen-lockfile` и запускать тот же `pnpm verify`, который используют локально и агенты.

## Возможный сервер

- Сервер при необходимости будет отдельным приложением `apps/api`.
- Предварительные кандидаты: Hono или Fastify; выбор откладывается до появления серверных требований.
- Контракты обмена выделяются вместе с API, без преждевременного общего domain-пакета.
- Локальная модель остаётся независимой от транспорта и серверной реализации.

## Изменение архитектуры

Материальные решения обновляются в этом файле. Отдельный ADR создаётся, только если решение требует сохранить альтернативы, последствия, миграцию или историю выбора, которые делают этот документ слишком подробным.

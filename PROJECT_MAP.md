# Карта проекта Trade Note

## Цель

Создать offline-first приложение для ведения личного инвестиционного портфеля. Пользователь вручную добавляет валюты и активы, изменяет или удаляет их и видит стоимость портфеля в USD, RUB и BYN.

## Текущее состояние

Статус: **фундамент проекта создан**.

Уже зафиксировано:

- монорепозиторий на pnpm workspaces;
- веб-приложение на Vue 3, TypeScript и Vite;
- Naive UI как коммерчески допустимая UI-библиотека;
- минимальная FSD-структура: `app`, `pages`, `shared`;
- один базовый экран портфеля;
- общие конфигурации TypeScript и ESLint вынесены в workspace-пакеты;
- подготовлена граница для собственной IndexedDB-библиотеки;
- настроены форматирование, линтинг, typecheck, тесты и сборка;
- добавлены инструкции и место для локальных skills агентов.

## Архитектурные решения

### Frontend

- Используем Composition API и `<script setup lang="ts">`.
- FSD-слои добавляются только при появлении реальной ответственности.
- Направление зависимостей: `app -> pages -> widgets -> features -> entities -> shared`.
- Внешние компоненты Naive UI импортируются точечно. Повторяемые обёртки помещаются в `shared/ui`.
- Router и Pinia не подключаются, пока приложение остаётся одноэкранным и не появляется общее изменяемое состояние.

### Хранение данных

- IndexedDB будет скрыта за собственной Promise-based библиотекой и репозиториями.
- `packages/indexed-db` не зависит от Vue и бизнес-моделей портфеля.
- Компоненты не обращаются к IndexedDB напрямую.
- Реактивное обновление планируется через явные события после успешной транзакции; межвкладочная синхронизация — через `BroadcastChannel` при необходимости.

### Финансовые значения

- Деньги, количество и курсы хранятся как канонические десятичные строки.
- Вычисления выполняются локальными функциями на основе `bigint` с явным масштабом и округлением.
- Обычный `number` не используется для сохраняемых финансовых значений.

### Адаптивность и PWA

- Предусмотрены два режима интерфейса: mobile/tablet и desktop.
- PWA подключается отдельным этапом после появления рабочего портфеля.

### Будущий сервер

- Предварительный кандидат — Hono; альтернативный зрелый Node.js-вариант — Fastify.
- Сервер будет отдельным приложением `apps/api`.
- Контракты обмена будут выделены только после появления API, без преждевременного общего domain-пакета.

## Ближайшие этапы

1. Спроектировать минимальный API собственной IndexedDB-библиотеки и правила транзакций.
2. Реализовать и протестировать финансовые примитивы: decimal string, scale, `bigint`, округление и конвертация валют.
3. Добавить FSD-сущности `asset`, `currency` и `portfolio`.
4. Реализовать добавление, изменение и удаление активов и валют.
5. Рассчитывать общую стоимость портфеля в USD, RUB и BYN.
6. Сделать адаптивные mobile/tablet и desktop-представления.
7. Добавить UI-тесты первого рабочего MVP.
8. Подключить PWA-манифест, service worker и offline-поведение.
9. После стабилизации локальной модели решить, нужен ли сервер и синхронизация.

## Пока не входит в проект

- авторизация и несколько пользователей;
- автоматическая загрузка котировок и курсов;
- импорт из CSV;
- несколько брокерских счетов;
- Vue Router, Pinia, TanStack Query и Turborepo;
- серверная база данных и API.

## Открытые решения

- точный формат инструмента и его идентификатора для акций, криптовалют, облигаций и индексов;
- правила округления стоимости и валютных конвертаций;
- модель ручных курсов валют и срок их действия;
- формат событий собственной IndexedDB-библиотеки;
- момент перехода от локального хранения к синхронизации с сервером.
